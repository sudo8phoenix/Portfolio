InvoChain

An invoice has a document. A payment has a record.

An Ethereum invoicing application connecting a familiar invoice workflow with wallet verification, smart-contract payments, generated PDFs and IPFS storage.

React · Express · Solidity · Ethers.js · Firebase · Pinata · pdf-lib

View repository ↗

01 / THE PROBLEM

Connect the pieces into a usable workflow.

An invoice document and its payment status often live in separate systems. InvoChain brings document generation, account identity and blockchain transaction tracking into one application, so users can create an invoice, retrieve its PDF and follow its payment state.

02 / SYSTEM ARCHITECTURE

Follow the data.

Conceptual flow, based on the repository documentation.

  1. 01

    Identity & wallet

    Firebase sign-in pairs with a nonce and wallet-signature verification flow.

  2. 02

    Invoice interface

    React provides creation, dashboard, profile and payment interactions.

  3. 03

    Contract & payment

    Ethers.js connects the application to Ethereum invoice contracts and MetaMask.

  4. 04

    Document storage

    Express generates PDFs with pdf-lib and uploads documents to Pinata IPFS.

Compared with a standalone invoice PDF generator, InvoChain adds wallet-linked identity and transaction visibility. Compared with a contract-only demo, it adds the interface, document services and retrieval needed for an end-to-end invoicing workflow. These are functional differences, not a measured speed or cost advantage.

03 / ENGINEERING DECISIONS

Why it works this way.

Separate documents from transactions

The system uses Ethereum for invoice and payment records and IPFS for generated PDFs. The practical benefit is that document storage has a separate responsibility from contract execution.

Verify wallet ownership explicitly

Google sign-in and control of an Ethereum address are different identity signals. The documented nonce and signature endpoints add proof of wallet control to the account workflow.

Give each layer a clear responsibility

React handles the interface, Express handles API and document services, and Solidity handles the contract layer. These boundaries make it easier to inspect and develop each part independently.

Make documents part of the product

Automatic PDFs include invoice and blockchain details. IPFS retrieval and dashboard filters connect the transaction mechanics to a workflow users can understand.

04 / EVIDENCE & LIMITS

What the docs establish.

The README documents invoice creation, ETH payments, transaction hashes, PDF generation, IPFS retrieval and profile verification. It lists Hardhat, frontend and backend test commands, but does not provide measured throughput, gas costs or a dated test-results report. This case study describes the documented design rather than claiming those checks passed.

Tradeoffs & next validation

Ethereum introduces gas costs and transaction confirmation delays; IPFS document availability depends on storage and gateway operations. Contract audit status, deployment reliability and document privacy need separate evidence. Using established libraries alone does not establish that the whole application has been audited.
