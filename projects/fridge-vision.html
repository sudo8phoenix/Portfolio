01 / THE PROBLEM

What needed solving.

A photo of a fridge is unstructured input. Recipe search needs ingredient names. This project connects a computer-vision model to a complete upload, detection and recommendation flow, with a local matching path and optional language-model generation.

03 / ENGINEERING

The decisions behind it.

Keep detection behind an API

The React interface sends the image to FastAPI. Ultralytics YOLO runs detection, while OpenCV and optional EasyOCR support image and label processing.

Use structured results for recommendations

Detected labels feed a local keyword matcher. Optional Ollama generation is a separate path, so the basic recipe workflow does not require a language-model service.

Treat quantities as approximate

Bounding boxes provide simple quantity estimates. They do not establish food weight, volume or nutritional content, especially under occlusion or inconsistent camera scale.

04 / EVIDENCE & LIMITS

Claims with context.

67Configured food classes
2Recipe paths: local matching or optional LLM

The README specifies YOLOv11-L, 800-pixel inference, confidence 0.25 and IoU 0.5. These are configuration values, not accuracy measurements. The repository includes a React upload experience and separate ingredient, recipe and combined API endpoints.

Current limits & next validation

No held-out mAP, per-class precision/recall or end-to-end latency benchmark was established in the reviewed documentation. Lighting, occlusion and packaging need testing. Recipe suggestions and approximate quantities do not establish dietary suitability or reduced food waste.
